# Project context: Profimann / Liquilob

Everything needed to work on this repository without having seen it before. Read this
first; then `README.md` for depth, `PHOTOGRAPHY.md` for imagery, `server/README.md` for the
switched-off server-side half.

---

## 1. What this is

A bilingual (Turkish / English) industrial website for **Profimann Makine San. Tic. Ltd.
Şti.**, a Konya-based engineering company, and its rotary lobe pump brand **Liquilob**.

Audience is industrial B2B: process engineers and purchasers specifying pumps for food,
dairy, chocolate, chemical, pharmaceutical, wastewater and general process duties. The site
sells credibility through precision and restraint, not through marketing energy. Nothing on
it claims a certification, a performance figure or a reference customer that Profimann has
not stated in writing.

Live at `https://www.liquilob.com`. Also currently served in full at `profimann.com` — see
§13.

---

## 2. Stack and hard constraints

Next.js 16 App Router, React 19, TypeScript, hand-written CSS on a token system.
**No UI framework, no CSS framework, no animation library, no state library.** Do not add
one; the absence is deliberate and the whole design system depends on it.

**The site is a static export.** `output: 'export'` in `next.config.ts`. `npm run build`
produces `out/`, and `out/` *is* the website. There is no Node process in production — the
host is Linux shared hosting (DirectAdmin, LiteSpeed, PHP).

This single fact drives most of the architecture:

| Consequence | How it is handled |
| --- | --- |
| No route handlers | Contact form posts to `public/inquiry.php` |
| No middleware | Locale redirect duplicated: `proxy.ts` for `next dev`, `public/.htaccess` for production |
| No image optimiser | WebP pre-generated by `tools/images.mjs` from masters in `assets/` |
| No runtime env | `SITE_STAGE` and `NEXT_PUBLIC_SITE_URL` are read at **build** time and baked in |
| No ISR, no server rendering | Every page is prerendered; `generateStaticParams` covers all 43 |

## 3. Commands

```bash
npm run dev        # localhost:3210 — design and content; the form cannot work here (no PHP)
npm run build      # prebuild (images + data) then next build -> out/
npm run typecheck  # tsc --noEmit; covers server/ and tools/, which next build does not
npm run images     # regenerate WebP from assets/
npm run data       # regenerate public/inquiry-data.json from content/
npm run preview    # php -S localhost:3211 -t out — serves the real artifact, form included
```

A production build needs both variables or robots.txt refuses every crawler (by design):

```bash
SITE_STAGE=production NEXT_PUBLIC_SITE_URL=https://www.liquilob.com npm run build
```

## 5. Language and URLs

Every page exists at a localised address; **there are no unlocalised routes**.

`lib/routes.ts` is the single table driving routing, `generateStaticParams`, header, footer,
sitemap and language switcher. Adding a page means adding one row there — they cannot drift
apart. Model codes (`lql-100`) are identical in both languages; application slugs are
translated (`sut-urunleri` / `dairy`).

Exported pages are directories (`trailingSlash: true`), so `/tr/urunler/` is
`out/tr/urunler/index.html`. The sitemap, the canonical tags and the address that returns
200 all agree on the trailing slash — keep it that way.

### The Turkish uppercase trap

`<html lang="tr-TR">` makes CSS `text-transform: uppercase` follow Turkish casing, so `i`
becomes `İ`. Correct for Turkish, wrong for the brand — `Liquilob` renders as `LİQUİLOB`.
Any uppercase label containing "Liquilob" or "Profimann" must already be uppercase in the
source string or be wrapped in `lang="en"`. This applies anywhere uppercase English appears
inside a Turkish document.

## 6. Content model

All copy lives in `content/`, every entry shaped `{ tr: '...', en: '...' }`, so a missing
translation is a TypeScript error rather than a silent gap.

| File | Holds |
| --- | --- |
| `site.ts` | Company facts: legal name, phone, address, domains |
| `dict.ts` | Interface strings: nav, labels, table headers, form chrome |
| `pages.ts` | Page prose, photo slots, the DOCUMENTS list |
| `products.ts` | Four LQL models and their specifications |
| `rotors.ts` | Four rotor geometries |
| `configurations.ts` | Jacketed and PP body variants |
| `applications.ts` | Seven application pages |
| `inquiry.ts` | Contact form fields and their email labels |

**One source of truth per fact.** Each model has one `specs` block; the catalogue card, the
comparison table, the key specifications and the data table all derive from it. Never
duplicate a value across renderings — that has already caused drift once and was fixed
deliberately.

## 7. Design system

Tokens are the contract. **Nothing outside `styles/tokens.css` introduces a colour, a type
size or a spacing value.**

- **One accent.** `--red` is `#cc0c0c`, sampled from the supplied logo artwork, not guessed.
  `--red-on-dark` is the variant that clears AA against `#141414`.
- **One shape rule.** Interactive elements 2px radius, containers 0px. Nothing rounder.
- **No shadows.** Depth comes from surface contrast and hairlines.
- **Four surfaces** — `--canvas`, `--cloud`, `--fog`, `--slab`. Two bands of the same
  surface never sit adjacent.
- **Numbers run mono.** Capacities, pressures, dimensions, phone number: IBM Plex Mono,
  tabular.
- **Red is never the only signal.** Active nav carries `aria-current` as well as red.

## 8. Drawings

Photographs sell the machine; drawings explain it. `components/graphics/` holds a side
elevation, a chamber cross-section, a curve frame and a dimensioned outline.

Rotor profiles in `rotors.ts` are **generated, not drawn**: one equation
`r(t) = a + b·cos(n·t)` at four lobe counts, bore held constant so the diagrams are
comparable. `node tools/rotors.js` regenerates them and refuses to emit a colliding pair, so
clearances are measured rather than asserted.

**Drawing styles live in CSS classes, never in SVG presentation attributes.** Browsers do
not resolve `var()` inside `fill="…"` — it silently paints black. Give drawing elements
classes from `styles/drawing.css`.

## 9. Motion and accessibility

**One motion effect on the whole site**: a short fade with 12px lift on viewport entry, from
a single `IntersectionObserver` in `components/ui/Reveal.tsx`. Server components mark
elements `data-reveal=""`; that is the entire contract, so shipped JavaScript does not grow
with page length.

**There is no scroll listener anywhere.** If you add scroll-driven behaviour, prefer CSS
`animation-timeline: scroll()` so this stays true, and check browser support against an
industrial audience on corporate IT.

Under `prefers-reduced-motion` the CSS shows everything immediately and the observer exits.

Accessibility rules in force: semantic landmarks, one `h1` per page, skip link to `#main`,
focus never removed (3px ink outline, white on slabs, **never red** — it vanishes against
the red CTA), spec tables scrollable inside a focusable `role="region"` with nothing hidden
on mobile, labels above inputs and never a placeholder as a label. Contrast: body 6.7:1,
muted 7.9:1, red/white 5.8:1.

## 10. The contact form

`components/forms/InquiryForm.tsx` posts JSON to `public/inquiry.php`, which validates and
emails it. The endpoint is `process.env.NEXT_PUBLIC_INQUIRY_ENDPOINT || '/inquiry.php'`.

**Field labels, the document list and the application list exist once.** `content/inquiry.ts`
describes them; `tools/inquiry-data.mjs` writes them plus the document and application maps
to `public/inquiry-data.json` at build time; `inquiry.php` reads that from disk. Adding a
field is a row in `content/inquiry.ts` plus an input in the form — **editing `inquiry.php`
to add a field is a mistake.** The JSON is denied over HTTP in `.htaccess`.

`inquiry.php` deliberately mirrors the Node route it replaced: same validation, honeypot,
field clamps, document whitelist, same TR/EN layout. It is written **backslash-free** (uses
`chr(10)`, `chr(13)`, `filter_var`) because the toolchain writing it mangles escapes.

The mailbox addresses live in `inquiry-config.php` **on the server only** — not in this
repository, and excluded from the deploy so a redeploy cannot overwrite them. Defaults in
`inquiry.php` are empty; an empty `$INQUIRY_TO` makes the endpoint answer 503 and the form
show the phone number, which is correct behaviour for an unconfigured build.

### Document requests

No catalogue or datasheet exists as a file yet, so every **Talep Et / Request** row routes
to the inquiry form, carrying its document id as `?doc=`. The form names the document above
the fields and submits it hidden; the email subject reads *Doküman talebi / Document
request* rather than the usual line, and the document is its first row.

The id is read from `window.location` in an effect, **not** `useSearchParams` — that keeps
the page prerenderable and is the only thing that works in a static export. The id is
validated against the document list on both sides; the endpoint is public and must never
echo an arbitrary string into the mailbox.

## 11. Images

Masters live in `assets/` and are **never served**. `tools/images.mjs` encodes web-sized
WebP into `public/` (and into `assets/` for the logo, which `Brand.tsx` imports statically
so Next fingerprints it — a copy in `public/` would ship twice). Currently 1,426 kB of
masters → 235 kB served.

Adding a photograph: master into `assets/photos/`, entry in `tools/images.mjs` with `width`
= widest rendered size doubled, `src` in `content/pages.ts`, then build. Never re-encode a
WebP from a WebP.

`tools/cad-cutout.mjs` keys SolidWorks viewport exports — flood-fills the gradient ground
inward from the border, crops, lifts the white point, unsharp masks. The fill only travels
through the ground, so white highlights inside the machine survive.

## 12. What is parked in `server/`

The site's server-side half — API routes, the `/admin` analytics dashboard, the event store,
the browser beacon, the Resend mailer — written, working, and switched off when the site
moved to static hosting. Nothing there is built or imported, but it is kept type-correct.
`server/README.md` explains what each file did, what replaced it, and the exact moves to
switch it back on.

Two of those decisions are reversible and may want reversing: log analytics cannot see a
click that requests no URL, and `inquiry.php` has no store, so a failed `mail()` loses the
enquiry. A small PHP inquiry log is the obvious fix and is the one thing PHP is genuinely
well suited to here.

## 13. Hosting, DNS and deployment

Registrar İsimtescil; hosting Güzel Hosting on DirectAdmin + **LiteSpeed** (so `.htaccess`
is honoured in full). Nameservers delegated to the host, so DNS including mail records is
managed in the panel. Account bought under `profimann.com`; `liquilob.com` added as a second
domain. Specifics are recorded in README → *How it is actually deployed*.

**Deployment is `git push` to `main`.** `.github/workflows/deploy.yml` builds and uploads
over FTPS to both document roots, incrementally, deleting what no longer exists.
`inquiry-config.php` and `.well-known/` are excluded so mailbox settings and certificate
renewals survive. Secrets: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`.

**HTTPS and the www redirect belong to the panel, not `.htaccess`.** The canonical block
ships commented out — configuring the same redirect in two places causes loops. Nothing is
lost by both hostnames answering: canonical tags and the sitemap name only the www address.

A review build made **without** the two env vars refuses every crawler and carries
`noindex`, so it is safe to upload anywhere. `.htaccess` names no hostname, so a temporary
address cannot redirect itself somewhere that does not exist.

## 14. Deliberately unfinished

- **Specifications are provisional.** `SPECS_ARE_PROVISIONAL = true` in `content/site.ts`
  renders a visible advisory on every spec table. The figures are dimensionally coherent but
  are not measured test data. When real data arrives, update the four `specs` blocks and set
  the flag false.
- **The document library does not exist.** Nothing links to a PDF that has not been issued.
- **`profimann.com` serves a full copy of the site.** Not a maintenance hazard — the
  pipeline updates both — but an open question: leave it, redirect it (302, not 301, and
  exclude `.well-known`), or build a corporate site there.

## 15. Traps that have already cost time

- **`npm run typecheck` must run after `npm run build`, never before.** `tsc` learns what a
  `.webp` import is from `next-env.d.ts`, which `next build` generates and which is
  gitignored. Fails only on a clean checkout — never on a tree that has ever been built.
- **Never zip the build with PowerShell `Compress-Archive` or Explorer's "Send to →
  Compressed folder".** Both write Windows backslashes as ZIP path separators, and Linux
  `unzip` produces 400 files with literal backslashes in their names. Use
  `tar -a -c -f ../site.zip .` from inside `out/`.
- **`npm ci` refuses a lockfile that disagrees with `package.json`.** After editing
  dependencies by hand, run `npm install --package-lock-only`.
- **Bash heredocs in this environment eat one level of backslash.** Writing files containing
  regexes or escapes via heredoc silently corrupts them; use the Write/Edit tools instead,
  and verify afterwards.
- **The local DNS cache lies.** Verify with `nslookup -type=a domain 8.8.8.8`, and test the
  live server with `curl --resolve host:443:IP`.
- **DirectAdmin `private_html`.** If HTTPS serves from it rather than `public_html`, the
  site looks perfect on http and empty on https. Use the symlink option.
- **The FTP account must be rooted at the account home (`/`)**, not at a domain directory,
  or it cannot reach both document roots.
- **Avoid `<If>` blocks in `.htaccess`** — not every LiteSpeed build honours them.

## 16. Working conventions

**Code comments explain *why*, and name the failure being prevented.** This repository's
comments are unusually explanatory and that is the house style — match it. A comment that
restates the code is noise; a comment that says "without this the artifact silently loses
.htaccess" is the standard.

**Commit messages are prose, not changelogs.** Imperative subject describing the change in
plain words, then paragraphs explaining the problem, the reasoning, what was rejected and
why, and what was verified. No bullet lists of files, no conventional-commit prefixes. End
with:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

**Documentation voice**: measured, specific, admits what is unfinished, no marketing
language. README, PHOTOGRAPHY.md and server/README.md all share it.

**Verify, do not claim.** Run the build, curl the live site, check the response headers,
read the file back. Report what was actually observed, and state plainly what was *not*
verified and why. Guessing at a cause twice and then reproducing it properly is better than
a confident wrong answer.

**Branch before committing to `main`**, unless explicitly told otherwise. Commit and push
only when asked.

**Answer decision questions with a recommendation**, not a survey of options. The user asks
"would it be better to X or Y" before implementation work and expects a clear pick with
reasoning, including pushback when the premise is off — then does the work once decided.

**Do not add dependencies casually.** The absence of frameworks is the design.
